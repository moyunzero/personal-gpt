# 知识库引用来源定量评测

日期：2026-09-25。原始分数在同目录 `results.json`，由 `yarn eval:citations` 写出。

## 结论

引用展示合同 24 条全部通过。Citation Precision 100%，Citation Recall 100%，禁止来源率 0%，编号泄漏率 0%。

同一次还跑了仓库已有的检索黄金集：冒烟 3 条、夜间 5 条断言通过（`tests/eval/phase-3`，25 条样本）。这两套都是确定性门禁，不包含对线上模型的忠实度打分。

## 评测集怎么设计

字段跟 RAGAS 的单轮样本对齐，再补上这个仓库原来就在用的引用约束：

| 字段           | 作用                 | 来源                                                        |
| -------------- | -------------------- | ----------------------------------------------------------- |
| `user_input`   | 用户问题             | RAGAS `SingleTurnSample`                                    |
| `reference`    | 这条样本应该怎样     | 同左的 `reference`                                          |
| `response`     | 带编号的回答         | 同左的 `response`                                           |
| `hits`         | 检索候选，含相似度   | 对应 `retrieved_contexts`，但保留分数，因为编号有 0.55 门槛 |
| `expectTitles` | 卡片上应出现的文档   | 本仓库 `expectCitationSource` 的多文档版                    |
| `forbidTitles` | 卡片上不得出现的文档 | 本仓库 `forbidSources`                                      |

已有的 `tests/eval/phase-3/golden.json`（25 条）继续测检索路径和意图：用户库 / 种子库分开，期望来源，禁止来源。那份文件没有被改写。新的引用合同集放在 `tests/eval/citation-alignment/golden.json`，单独验收「卡片等于回答点名的材料」。

分层按失败方式切开，而不是按书名切开。24 条落在 6 组：

| 组                 | 条数 | 在测什么                                                                                          |
| ------------------ | ---- | ------------------------------------------------------------------------------------------------- |
| 指定文档           | 6    | 点名一本书时，卡片只有这一本。含改写问法、checkpointer 文档                                       |
| 未采用的邻居       | 3    | 高分邻居被召回但正文没点名，卡片里不能出现。含用户库不得带出种子心理学语料                        |
| 相似度门槛         | 3    | 低于 0.55 的片段不进入编号。最高分也不过线时，正文里的 `[S1]` 不能造出卡片                        |
| 通识、无关、空检索 | 4    | 不写编号则卡片为空。质数、换算、日期、空库                                                        |
| 卡片合并           | 2    | 同一文档两个片段一张卡；两篇文档都被采用则两张卡                                                  |
| 编号形态           | 6    | `【S1】`、`［S1］`、先写 S2 再写 S1、重复编号、越界 `[S9]`、`[S10]` 不被截成 S1、可见正文去掉编号 |

读书笔记用的是库里真实书名：《不要挑战人性》《哈佛家训》《活下去的理由》《天才在左疯子在右》。工程文档用的是黄金集里已有的标题，避免另造一套语料。

## 指标

跑分路径和线上一致：相似度不低于 0.55 才编号，然后 `filterCitationsBySourceMarkers`，再 `stripSourceMarkers`，最后按 `documentId` 合并卡片。

- Citation Precision：展示标题里属于期望标题的比例。期望和展示都空，记 1。
- Citation Recall：期望标题里被展示出来的比例。期望为空且展示为空，记 1。
- Forbidden Source Rate：展示中出现禁止标题的样本比例。门禁 0。
- Marker Leak Rate：用户可见正文仍含 `[S数字]`、`【S数字】` 或 `［S数字］` 的样本比例。门禁 0。
- Contract Pass Rate：单条上四项都成立的比例。门禁 100%。

空引用记满分，是因为通识回答本来就不该有卡片。若模型用了材料却没写编号，合同把它当成没有引用，卡片为空。那是已知缺口，本表不把它记成展示错误，也不把它记成忠实度。

## 这些数字不能说的事

引用集里的 `response` 是按合同写好的回答，用来检查过滤和展示。它不是把问题重新丢给线上模型后记下的输出。因此 100% 只说明展示代码按编号过滤、按文档合并、并擦掉编号。它不说明模型会不会漏写编号，也不说明答案是否被片段支持。

检索黄金集的夜间用例把期望命中直接放进 mock 向量库。通过只说明混合检索会把这个来源送回来，并且不会凭空插入禁止来源。它不是在真实向量库上测的 Recall@K 或 MRR。

`tests/eval/EVALUATION-STANDARD.md` 里的 Faithfulness ≥ 0.85、Answer Relevance、幻觉下降，这次没有测。没有调用 RAGAS 或 OpenEvals 的裁判模型，所以报告里不给这些分数。

## PDF 切块和入向量库

入库是 `pdf-parse` 只抽文字层，再按 900 字、重叠 100 字做递归字符切块，整段写入向量库。块上有 workspace、文档、标题和块序号。重索引先删再插。读书笔记用这个默认值可以。这 8 份 PDF 不是最佳实践。2026-09-25 用同一套解析量过：

| 文件                                    | 抽出的文字                              | 入库块数          |
| --------------------------------------- | --------------------------------------- | ----------------- |
| sample-pdf-2mb / 5mb / 10mb             | 167 / 437 / 887 字，只有 “-- 1 of N --” | 各 1              |
| frostbite 年报                          | 1212 字，表格被拉成一行行数字           | 3                 |
| sample-pdf-tiny / small / 100kb / 500kb | 0.6 万到 9.6 万字 Lorem ipsum           | 9 / 27 / 72 / 140 |

2MB、5MB、10MB 几乎是图片，文字层是空的，系统仍标成 ready，向量里只有页码。年报表格没有按行切开，块上没有页码。笔记和 PDF 用同一套字符切块，不按 Markdown 标题断开。

更稳的做法是：抽不出正文就不要标成已入库；PDF 保留页码；表格按行切；笔记按标题切。当前实现对普通正文够用，扫描件和财务报表会把空页码或拆开的数字送进检索。
