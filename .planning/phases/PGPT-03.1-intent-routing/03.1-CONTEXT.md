<domain>
## Phase Boundary

Phase 3 交付了 Graph RAG **能力栈**，但 Chat/Agent **路由割裂**，Agent Graph 依赖 LLM 自选工具（H-04 partial）。

本阶段建立 **统一 Intent Router（Shared Kernel）**，输出 `IntentPlan`，Chat 与 Agent 共用 **意图分类 + 工具白名单 + Fallback 链**。

**In scope:**
- `packages/shared/src/routing/` — IntentPlan、L0/L1/L3、可选 L2
- Agent：plan-driven execution、single_specialist、tool 白名单、KB→Graph fallback、trace
- Chat：shared router + **graph inject + 可折叠「图谱路径」卡片**（类 citation）
- 回归：`07-intent-routing.test.ts` + golden 扩展

**Out of scope（Deferred to Phase 4+）：**
- 用户可见「模式切换」UI toggle（Phase 4 Wave 1 PROD 或更晚）
- **应用级 Graph KB**（ingest 构图、实体 catalog、非 seed 路由）→ Phase 4 Wave 0（GRAPH-01–04）
- 独立路由 Agent 子图、全库 NER、Chat 完整多 Agent
- LLM Text2Cypher / GraphRAG 社区摘要 → Phase 5
- RAGAS / 新存储后端

</domain>

<decisions>
## Implementation Decisions

### D-01: Shared Kernel 位置
- 意图路由核心放在 `packages/shared/src/routing/`，Chat 与 Agent 均从此 import
- 禁止 web 与 agent-service 各维护平行路由逻辑

### D-02: IntentPlan 契约
- `PrimaryIntent`：`chitchat | general | kb_doc | graph_relation | kb_graph_hybrid | web_research | analytics | report | multi_step`
- `RetrievalChannel`：`none | kb | graph | kb+graph | web`
- 必填：`primary`, `channels`, `specialists`, `retrieverTools`, `fallbackChain`, `reason`, `confidence`
- `retrieverTools` = **硬白名单**，Retriever 不可自选全集

### D-03: 四层路由引擎
- **L0** 规则快路径：寒暄、算式、Graph 关系词、多步关键词（含 graph 语义）
- **L1** 信号探测：KB embedding 预检 + `resolveProductName` 实体规则（无 live Neo4j EXISTS）
- **L2** 可选 JSON 分类器 — **默认关**（见 D-14）
- **L3** `synthesizeIntentPlan` 合并各层 + 默认 fallbackChain

### D-04: Agent 执行模式优先级
1. `chitchat` → short 短路
2. `specialists.length >= 2` → Sequential（见 D-12）
3. `specialists.length === 1` → **single_specialist**（见 D-11）
4. 仅 ambiguous → Supervisor hub-and-spoke

### D-05: Fallback 链（服务端 deterministic）
- **触发条件（D-13）：** 仅当 `plan.fallbackChain` 含 `graph_search` **或** L0/L1 曾有 graph 信号时，KB `NO_RELEVANT_HIT` 才 auto `invokeGraphSearch`
- `graph_relation` 无路径 → 低优先级 fallback `kb_search`
- 禁止仅靠 prompt 建议；必须在 `agent.service.ts` 执行

### D-06: Graph 意图 L0（H-04 锚点）
- 实体关系模式 + 种子实体（珍珠奶茶等）→ `graph_relation`, `retrieverTools=["graph_search"]`
- Agent UI trace **必见** `graph_search` + `GRAPH_SEARCH_STATUS: HIT`

### D-07: Chat 路由与 Graph 呈现
- `query-router.ts` 薄包装 `resolveIntentPlan`
- `chitchat/general → direct`；`kb_doc → retrieve`
- **`graph_relation` → `graphRagQuery` inject system prompt + 回答下方可折叠「图谱路径」卡片**（类似 citation；**不展示 raw Cypher**）

### D-08: 可观测性
- `AgentTraceIntent` 扩展：`plan`, `routerLayers`, `route`（含 `single_specialist`）
- **双层展示（D-15）：** 步骤面板中文简化（如「图谱检索」）；Trace 面板可展开完整 IntentPlan JSON

### D-09: 测试门禁
- `07-intent-routing.test.ts` ≥8 cases；珍珠奶茶断言 `retrieverTools` + `invokeGraphSearch`
- golden ≥3 intent cases；Phase 1 #06 + Phase 2 #04 不回归

### D-10: 配置开关
- `ENABLE_INTENT_ROUTER=true`（默认开）
- `ENABLE_KB_GRAPH_FALLBACK=true`（默认开）
- Neo4j 不可用 → degrade `kb_doc` + trace reason（fail-open）

### D-11: single_specialist 形态（discuss-phase）
- **服务端 prefetch `graph_search`（或 kb）+ Retriever LLM 复述**
- 工具调用必须在 stream 前/初段发生；禁止回到「仅 Retriever 自选工具」

### D-12: 多步专科顺序（discuss-phase）
- **按用户话术关键词首次出现顺序**排专科
- 并列 tie-break：`retriever → researcher → analyst → editor`
- Graph 意图 → retriever 仅 `graph_search`；可与 kb retriever 分步出现

### D-13: Fallback 激进度（discuss-phase）
- **非**所有 KB miss 都试 graph
- 仅 fallbackChain 含 graph **或** L0/L1 graph 信号时 auto graph

### D-14: L2 默认策略（discuss-phase）
- **L2 默认关**；`ENABLE_L2_INTENT_CLASSIFIER=true` 时才在 L0/L1 不足时调用
- H-04 靠 L0 硬路由，不依赖 L2

### D-15: Trace 展示粒度（discuss-phase）
- 用户向：步骤/todo 中文标签
- 开发者向：AgentTracePanel 可展开完整 `IntentPlan`（现有 `data-agent-trace` 载荷）

### D-16: 灰色意图默认（discuss-phase）
- Chat：**灰色地带默认 retrieve**（延续 embedding 灰区「宁可多检」）
- Agent：仅 plan ambiguous 时进 Supervisor；single intent 不得 Supervisor 直答

### Claude's Discretion
- L2 prompt / Zod schema 字段命名
- 「图谱路径」卡片 UI 细节（折叠样式对齐现有 citation 组件）
- 单测 mock 策略（fixture vs spy）

</decisions>
