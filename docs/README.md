## 各章写作要求

### 文首元信息（`> ` 引用块）

| 字段 | 必填 | 说明 |
|------|------|------|
| **分支** | ✅ | 关联的 git 分支名 |
| **范围** | ✅ | 影响的包/目录，一句话 |
| **栈** | ✅ | 主要依赖及版本（运行时、框架、语言） |

### TL;DR

- 3–5 句话，说清 **做了什么、用什么、解决什么痛点**
- 不写实现细节；读者 30 秒内能判断是否要继续读

### 1. 背景与目标

| 小节 | 内容 |
|------|------|
| **要做什么** | 表格：能力 · 状态（✅ / 部分 / 占位）· 说明 |
| **非目标** | 列表：本阶段明确不做的事，避免范围蔓延 |

### 2. 技术选型

- 表格：**层级 · 选择 · 理由**（至少 3 行）
- 只写本 Phase **实际采用**的技术，不写未落地的备选长篇对比

### 3. 架构总览

| 小节 | 内容 |
|------|------|
| **3.1 分层图** | Mermaid `flowchart`，区分入口 / UI / 逻辑 / 数据 / 终端适配等 |
| **3.2 依赖方向** | 文字或图：谁依赖谁，强调单向、禁止循环 |

### 4. 知识点思维导图

- Mermaid `mindmap` 或 `flowchart`，概括本章涉及的技术概念
- 与第 7 章知识点编号呼应（便于跳转）

### 5. 模块与关键代码

**每个模块**按同一四段式书写（顺序固定）：

1. **通俗说明** — 非技术人员能懂的一句话职责
2. **类比**（可选）— 生活/产品类比
3. **带注释代码** — 摘录关键代码，注释用中文解释「做什么、为什么」
4. **关键逻辑** — 表格 / ASCII 示意图 / 简短流程，不重复贴大段代码

章末建议有 **模块关系总览**（Mermaid + 一句话职责表）。

### 6. 核心流程

- 至少 1 个 **时序图**（`sequenceDiagram`）或 **流程图**（`flowchart`）
- 覆盖主路径：启动、核心交互、关键数据流
- 与第 5 章代码对应，不引入第 5 章未提到的模块

### 7. 知识点详解

章首说明：每节含 **概念表（含官方参考链接）+ 是什么 + 本仓库代码/命令/curl 示例 + 落点**。  
**例子和用法必须写在正文**；官方链接作延伸阅读，不替代正文。

每个知识点小节（`7.1`、`7.2`…）固定结构：

```markdown
### 7.x {知识点标题}

| 概念 | 说明 | 参考 |
|------|------|------|
| … | … | [官方文档](url) 或 — |

**是什么**：…

**用法示例**（TypeScript / bash / JSON 至少一种）：

\`\`\`typescript
// 本仓库实际调用方式
\`\`\`

**本仓库落点**：`path/to/file.ts`
```

章末建议 **速查表**：知识点编号 · 源文件 · 官方参考。

### 8. 文件索引

- 表格：**文件路径 · 层级 · 一句话职责**
- 路径相对于仓库根目录（如 `app/api/chat/route.ts`）

### 9. 开发与调试

| 小节 | 内容 |
|------|------|
| **启动** | 可复制的命令（从仓库根目录） |
| **环境/配置**（按需） | 一次性 setup、环境变量 |
| **调试 checklist** | 表格：现象 · 排查步骤 |

### 10. 已知限制与后续

| 小节 | 内容 |
|------|------|
| **已知限制** | 诚实列出 bug、终端差异、未实现项 |
| **后续 Phase 建议** | 短列表，可带优先级 |

### 附录（可选）

- 用户可见的枚举：命令表、快捷键表、配置项等
- 表格列保持一致：**名称 · 类型/状态 · 当前行为**

## Markdown 与格式约定

| 项 | 约定 |
|----|------|
| 章节分隔 | 主要章节之间用 `---` |
| 代码块 | 标明语言：`` ```tsx ``、`` ```ts ``、`` ```bash `` |
| 代码注释 | 文档内注释用 **中文**；仓库源码注释用 **英文**（与代码风格一致） |
| 图表 | 优先 Mermaid；复杂 UI 可用 ASCII 框图 |
| 链接 | 官方文档用完整 URL；仓库内用相对路径 |
| 表格 | 表头加粗与否保持一致；列名简短 |
| 状态符 | ✅ 完成 · ⚠️ 部分 · ❌ 未做/不支持 |
