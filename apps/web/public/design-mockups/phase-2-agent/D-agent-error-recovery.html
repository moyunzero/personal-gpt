Agent 失败时，要停在「可恢复」

现状：流断掉后只在输入框下方留一行灰色小字（如 403 status code (no body)），进度还停在「进行中」，用户以为卡死。 设计目标：把真实错误翻译成人话，固定在对话流里，并给出下一步。

1. 错误进主视线

放在助手气泡区域，不挤在 composer hint。

2. 按类型讲人话

403 / 429 / 网络 / 模型限流 各有标题与建议，原文可折叠。

3. 进度诚实收尾

「进行中」改「失败」，待办不再假装还能继续。

错误类型映射（同一卡片骨架，换文案）

HTTP 403

服务拒绝了这次请求

密钥无效、模型无权或网关拦截。可重试；仍失败请检查 Agent 配置。

HTTP 429 / RATE_LIMIT

请求太频繁，被限流了

稍等片刻再试。复杂任务消耗大，可缩短问题或拆成两步。

Failed to fetch / ECONNREFUSED

连不上 Agent 服务

请确认本机 agent-service（:3002）已启动，或检查 NEXT_PUBLIC_AGENT_SERVICE_URL。

MODEL_NOT_FOUND / tool validation

模型或工具调用失败

当前模型不可用，或专科交接参数不合规。可换模型/提供商后重试。

实现约定（设计 → 开发）

  1. 解析 error.message / status：映射为 title + advice + code，禁止只甩原始字符串。
  2. 消息区渲染 AgentErrorCard（流结束后、!isStreaming）；composer hint 恢复普通提示。
  3. 若有步骤面板：active → error；文案改为「执行中断」。
  4. 主按钮：用同一 user 文本再 sendMessage；次按钮：切回 Chat。
  5. 技术细节默认折叠；不展示密钥。若已有 data-agent-trace，卡片下方仍可显示轨迹。
